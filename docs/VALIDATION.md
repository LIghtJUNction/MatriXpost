# MatriXpost 0.5.0 验收记录

验收日期：2026-11-20（Asia/Taipei）。

## 结论与适用范围

本版本可作为 Chromium 开发预览扩展安装，具备统一的视频与商品草稿、独立 API 账号凭证、发布检查、持久化任务队列及 MCP 操作接口。核心与协议测试 72 项通过；真实 Chromium 浏览器检查 12 项通过。

平台目录包含 31 个入口：YouTube、WooCommerce、Shopify 有已实现的官方 API 请求流程，其余 28 个提供创作或商家后台入口、文案准备和通用字段辅助。本次没有使用真实平台账号发布视频或上架商品，也没有把目录入口数量视为自动发布平台数量。

源码与完整使用说明：[LIghtJUNction/MatriXpost](https://github.com/LIghtJUNction/MatriXpost)。平台所需权限与当前限制见 [平台矩阵](https://github.com/LIghtJUNction/MatriXpost/blob/main/docs/PLATFORMS.md)。

## 本轮修复与证据

浏览器联调发现：具有站点权限的 Chromium 扩展 GET 请求可能不携带 Origin，而桥接轮询要求精确的配对扩展 Origin，因此出现 HTTP 403。扩展现使用 JSON POST 轮询，由浏览器生成 Origin；服务端仍校验 Host、Bearer 配对码和精确扩展 Origin。实际浏览器记录确认 POST 轮询与结果提交均来自配对扩展并返回 200。

远端草稿转正式发布复用原视频或商品 ID，避免创建重复资源。对应协议测试核对 YouTube 可见性更新、WooCommerce 原商品更新，以及 Shopify 原商品渠道发布。核心同时拒绝同一内容与账号的并发草稿/发布动作。

未知创建结果保留为“结果待核对”，不会自动重发非幂等创建。上传进度和远端 ID 持久化；可恢复操作按平台已确认状态继续。素材清理只删除未被草稿或未完成任务引用的文件，失败任务的素材仍然保留。

## 使用前应理解的边界

API 账号的凭证彼此独立；页面会话账号使用当前浏览器配置的登录会话，同站点标签页不会自动隔离 Cookie。需要多个独立页面账号时，应使用不同浏览器配置。本版不读取 Cookie，也没有自动切换全部平台登录身份的能力。

YouTube token、店铺 key/token 由使用者自行取得和配置。本版未提供 OAuth 登录应用注册、自动刷新和所有平台账号身份核验。YouTube 既有视频更新需要相应更新权限；Shopify 库存与渠道发布还需要实际 Location / Publication ID。

定时任务要求浏览器运行，API 派发要求保险箱解锁；关闭浏览器不会让定时任务继续执行。页面辅助模式需要在官方后台完成素材上传、平台特有字段与最终提交。商品适配器当前覆盖简单商品或单规格商品，复杂规格、税务、物流和资质流程尚未实现。

Firefox、Safari、浏览器商店发行和全部平台自动发布不在本次已验证交付范围内。当前安装方式是解压安装包，在 `chrome://extensions` 中加载其中的 `chromium` 文件夹；可选 AI 桥接运行步骤见随包的 `bridge/README.md`。
