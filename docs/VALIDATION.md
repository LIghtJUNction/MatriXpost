# MatriXpost 0.6.0 验收记录

验收日期：2026-11-20（Asia/Taipei）。对应版本：`v0.6.0`。上一版记录保留在 [0.5.0 验收记录](VALIDATION-0.5.0.md)。

## 结论与范围

本轮完成创作界面、账号接入、发布检查与任务恢复改进。核心与协议测试 79 项通过；真实 Chromium 扩展验收 19 项通过。使用隔离浏览器配置与测试数据，未修改使用者已有的草稿、凭证、素材或任务。

YouTube、WooCommerce、Shopify 已实现官方 API 请求流程并通过协议 fixture。另有 28 个平台提供后台入口与页面辅助。此次没有真实平台账号发布或上架记录，逐平台现场状态见 [平台矩阵](PLATFORMS.md)。

## 0.5.0 → 0.6.0 更新

升级使用 `d9dacc4e88bd176a734e38bd0b23b96b480f7b09` 中的真实 0.5.0 扩展，在隔离配置里创建旧数据，再在相同安装目录覆盖 0.6.0，保留浏览器配置与扩展 ID。

升级检查 **8 / 8 通过**。六个 IndexedDB 存储表逐对象一致：3 条草稿、1 个 API fixture 账号、2 个任务、1 个素材、2 条设置和 1 条密文。视频 Blob 共 4,097 字节，逐字节与 SHA-256 一致；原口令成功解密旧密文。浏览器完整退出后，会话密钥在扩展重新加载之前已清除。

已取消任务仍保持停止，保留原远端 ID；未知创建结果仍为 `uncertain`，重试返回 `OUTCOME_UNCERTAIN`。打开、解锁和检查任务后，六个存储表仍与升级前完全一致。页面错误、外网尝试和站点授权均为 0。

这项检查使用 headless Chromium，通过真实扩展管理页的“开发者模式”开关和“重新加载”按钮完成更新。账号与任务是明确的存储 fixture；凭证由真实 0.5.0 的 Vault 加密，没有请求或模拟权限。它与上节带原生权限窗口的 19 项有界面验收是两套独立检查。

升级视频 fixture SHA-256：`74e47eeac0274c4d2be5af27c0ef19637ba728dbc0a21b14f781e1937cefbeba`。

现场发现：仅覆盖扩展文件后重启 Chromium，可能出现清单版本已更新而后台 service worker 仍运行旧代码的情况。因此 [安装指南](INSTALL.md) 要求在 `chrome://extensions` 中明确点击“重新加载”，再关闭旧标签页并重开工作区。没有采用卸载、清空浏览器数据或改变扩展目录的方式升级。

## 复现与证据文件

```sh
npm run check
npm test
npm run build
node scripts/release-check.mjs v0.6.0
```

真实浏览器检查使用 `scripts/browser-test.mjs`，通过 `MATRIXPOST_PLAYWRIGHT_MODULE` 指定开发环境的 Playwright，`MATRIXPOST_CHROMIUM` 指定 Chromium。原生权限模式需要独立 Xvfb / D-Bus，并在实际窗口中点击允许。具体启动方法见 [README](../README.md#开发与验收)。升级检查使用 `scripts/upgrade-test.mjs`。

原始报告在开发机 `test-results/browser-smoke.json`、`test-results/upgrade-smoke.json`。发布验收包保留报告、截图和本记录；对外副本去除临时配置路径、Xauthority 路径与进程号。安装包与验收包随 GitHub Release 交付，并尝试同步 Google 云盘。
