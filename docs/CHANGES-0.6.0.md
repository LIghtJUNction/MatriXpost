# MatriXpost 0.6.0 改动说明

这次更新集中处理写内容、接账号、检查发布和接着做未完成任务这四件日常工作。版本仍为 Chromium MV3 开发预览。

## 创作和界面

- 改为浅色侧栏、清楚的字段层级和更宽的留白，去掉英文装饰、宣传语和 AI 推介块。深色主题使用相同的布局。
- 将 YouTube 专用字段、商品高级字段和计划时间折叠，常用输入留在主区域。全选页面辅助账号时收起 API 动作与定时选项，按钮直接说明会打开平台后台。
- 标题非空、字段有效后，停止输入约 900 ms 自动保存。页面刷新或重新打开工作区会继续上次的草稿、目标账号、动作和本地计划时间。
- 两个窗口同时编辑同一草稿时，旧窗口不会覆盖新修订；保留当前输入并提供“另存副本”。
- 在创作页新加账号会自动选择这个目标，减少来回切页。

## 接入和发布检查

账号接入页按平台给出所需地址和授权字段。账号备注、已存凭证和真实授权状态分别说明，避免把录入成功当成平台身份已经核验。

发布前展示当前内容、目标账号、执行方式和缺失条件。只有通过检查的目标会加入队列，确认按钮标明数量。若旧修订已经有远端内容，检查页会提醒当前修订将另建内容。

页面辅助账号仍需在官方后台核对登录身份，完成平台特有字段、文件上传与最后提交。

## 任务恢复与重复创建

已保存远端视频、商品或上传会话的取消任务，重新加入同一内容版本、账号和动作时会返回原任务。用户可以选择“继续原任务”，沿用已保存的进度。相关视频素材继续被引用，清理操作不会将其当作废弃文件删除。

WooCommerce / Shopify 已完成的前置检查可以安全恢复；Shopify 已保存商品、规格和库存对象时按已有检查点继续。AI 恢复公开发布仍须工作区批准。

请求已经发出但创建结果未知时，任务保留“结果待核对”，不会自动再次创建。任务页提供平台核对入口。WooCommerce 入口保留站点的 WordPress 子目录。

这些去重规则针对同一内容修订。修改草稿会产生新修订；本版尚未提供任意新修订覆盖旧远端内容的功能。

## 安装与交付

- main 和 Pull Request 工作流在 Node.js 22、24、26 执行检查、测试、构建和安装包验证。
- 版本 tag 对应的 Release 工作流生成 Chromium 包、AI 桥接包、完整包和 SHA-256 校验文件，通过检查后公开为开发预览 Release。
- 安装指南说明包的选择、加载目录、AI 连接和故障排查。更新时保留原目录与扩展 ID，并在扩展管理页点击“重新加载”。
- 0.5.0 验收记录保存在独立文件中；平台矩阵逐项区分协议测试与真实平台现场验收。Project Z 关系按实际代码登记，当前没有该依赖。

## 验收范围

本轮执行源码检查、79 项核心与协议测试、构建与安装包校验。真实 Chromium 的 19 项检查覆盖自动保存、两窗口冲突、素材字节、账号密文、原生权限窗口、MCP 往返、360 / 420 px 六个视图、深色主题和完整浏览器重启。另用 0.5.0 的真实扩展创建旧数据，验证更新到 0.6.0 后的数据保留。

最终结果与复现方法见 [验收记录](VALIDATION.md)，安装步骤见 [安装指南](INSTALL.md)。

本轮没有真实平台发布或上架记录。YouTube、WooCommerce、Shopify 的官方 API 实现通过协议 fixture；另外 28 个平台仍是后台入口与页面辅助，现场状态见 [平台矩阵](PLATFORMS.md)。
