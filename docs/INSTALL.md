# 安装与更新 MatriXpost

先从 [Releases](https://github.com/LIghtJUNction/MatriXpost/releases) 下载安装包。当前版本是 Chromium MV3 开发预览，尚未上架浏览器商店；实际测试的浏览器和系统见 [验收记录](VALIDATION.md)。

## 选哪个安装包

| 文件 | 适合的情况 |
| --- | --- |
| `MatriXpost-chromium-版本号.zip` | 只使用浏览器扩展。大多数人选择这个包即可。 |
| `MatriXpost-版本号.zip` | 同时需要扩展、AI 桥接和完整文档。 |
| `MatriXpost-ai-bridge-版本号.zip` | 扩展已经安装，只补充本机 MCP 桥接。 |
| `SHA256SUMS` | 下载后核对 ZIP 文件的完整性。 |

GitHub 自动提供的“Source code”文件是源码包。它需要先构建，不能直接作为已打包扩展加载。

## 第一次安装

1. 解压下载的 ZIP，把解压目录放在以后不会随手删除的位置。
2. 在 Chromium 地址栏打开 `chrome://extensions`。
3. 打开“开发者模式”，点击“加载已解压的扩展程序”。
4. 选择直接包含 `manifest.json` 的目录。扩展专用包的根目录就是这个目录；完整包需要选择其中的 `chromium` 目录。
5. 确认扩展列表中出现 MatriXpost。点击工具栏中的扩展按钮，再点击 MatriXpost，打开工作区。

扩展要求 Chromium 120 或更高版本。其他 Chromium 发行版需要按自己的扩展管理页安装，兼容情况以实际验收记录为准；Firefox 和 Safari 版本尚未交付。

### 打开以后做什么

先创建一份草稿，再在账号页选择准备使用的平台。API 账号需要设置保险箱口令、填写自己的授权信息；页面会话账号使用当前浏览器已登录的后台。同一浏览器配置中的同站点标签页共享登录状态。

平台地址的权限窗口是浏览器正常提示。核对窗口中的站点与准备接入的平台一致后再允许；拒绝以后可以重新执行接入操作。扩展不会隐藏或替换这个窗口。

保存草稿后，选择目标账号并检查发布计划。检查页面会说明还缺什么、哪些目标通过检查以及后续的操作方式。第一次使用先保存到平台草稿或私密视频；正式发布前确认内容、账号和可见性。

## 更新时保留现有数据

更新前先等正在提交的任务结束。可以导出一份元数据备份；备份只包含草稿、账号标签和历史，不包含凭证、口令、上传会话地址或视频文件。

1. 记下当前扩展 ID 和已加载目录。
2. 把新版 ZIP 解压到临时目录，确认其中包含 `manifest.json`。
3. 用新版扩展文件替换原来加载目录中的文件，**保留原目录路径**。
4. 回到同一浏览器配置的 `chrome://extensions`，点击 MatriXpost 卡片上的“重新加载”。
5. 再次打开工作区，核对版本、扩展 ID、草稿、素材、账号和任务列表。

不要先点击“移除”，也不要把新版加载为另一个扩展。移除扩展可能清除本地数据；改变未打包扩展的目录可能产生新的扩展 ID，使浏览器使用另一份存储。

扩展程序文件与浏览器保存的数据分开存放。按原路径重新加载会继续使用该扩展的存储，但这不能替代完整数据备份。若更新后看不到旧数据，先核对是否用了原来的浏览器配置、目录和扩展 ID，不要清理浏览器数据。

### 浏览器重启与任务恢复

重启浏览器后，草稿、素材、账号和任务应继续显示，保险箱需要重新输入口令。计划任务依赖浏览器运行和保险箱解锁；浏览器关闭时不会执行。

如果任务显示“结果待核对”，先打开对应平台后台查看视频或商品是否已经创建，再按任务页提示处理。不要通过新建相同任务来试探平台结果，以免重复发布。

## 使用 AI / MCP（可选）

普通创作和发布不需要安装 AI 桥接。需要让 AI 操作草稿或任务时，安装 Node.js 22+，解压完整包或桥接包，并复制扩展管理页中的实际扩展 ID：

```sh
node bridge/cli.mjs serve --extension-id YOUR_CHROMIUM_EXTENSION_ID
```

保持这个终端运行，在扩展的 AI 页面输入终端显示的本机地址和配对码。MCP 客户端的配置和凭证传递方式见 [桥接说明](../bridge/README.md)。配对期间保持工作区页面打开。

AI 发起的公开发布默认需要在工作区核对后批准；AI 不能自行解锁保险箱或批准公开发布。

## 常见问题

| 看到的情况 | 下一步 |
| --- | --- |
| “无法加载扩展程序”或找不到清单 | 选择直接包含 `manifest.json` 的目录，检查是不是多选了一层 ZIP 解压目录。 |
| 扩展列表出现两个 MatriXpost | 先按扩展 ID 和加载路径找回原来的那个。确认数据所在位置前不要移除任何一个。 |
| 更新后页面还是旧样式 | 在扩展管理页重新加载，再关闭旧工作区标签页并重新打开。 |
| API 账号保存或检查失败 | 按具体错误核对站点权限、HTTPS 店铺地址和授权信息；不要把 token/key 发到公开 Issue。 |
| 页面账号打开了另一个身份 | 同站点标签页共享当前浏览器配置的登录会话。需要隔离账号时，使用不同浏览器配置。 |
| 浏览器重启后任务没有继续 | 重新解锁保险箱，检查任务是否到期；“结果待核对”需要先核对平台。 |
| 配对码正确但 AI 没有响应 | 确认桥接终端仍在运行、扩展 ID 与启动参数一致，并保持扩展工作区打开。 |
| 下载包没有通过校验 | 重新从同一个 Release 下载 ZIP 和 `SHA256SUMS`，不要混用不同版本的校验文件。 |

## 从源码构建

使用 Node.js 22+，在仓库目录执行：

```sh
npm run check
npm test
npm run build
node scripts/release-check.mjs
```

这些步骤不需要 `npm install`。加载 `dist/chromium`，或使用 `dist/` 中的 ZIP。Linux/macOS 可以在安装包目录使用 `sha256sum -c SHA256SUMS` 或 `shasum -a 256 -c SHA256SUMS`；Windows PowerShell 使用 `Get-FileHash 文件名 -Algorithm SHA256`，与校验文件对应行比较。

## CI 与版本发布

提交到 `main` 或发起 Pull Request 后，工作流会在 Node.js 22、24、26 上执行检查、测试、构建和安装包验证。Node.js 24 的构建会上传 Actions artifact。真正的浏览器操作和原生权限窗口由现场验收覆盖，结果记入 [验收记录](VALIDATION.md)。

维护者把 `package.json` 与扩展清单更新到同一版本，确认本地验收后推送对应的 `v版本号` tag。Release 工作流重新运行检查，通过后上传三个 ZIP 和 `SHA256SUMS`，最后公开为 prerelease。版本不匹配或任一步失败时不会公开新的完整 Release；上传中断会保留草稿，重新运行可以补完草稿。已公开的同版本资产不会被自动覆盖。
