# MatriXpost

**把视频、商品和多个账号放进一个发布工作区。**

MatriXpost 0.5 是一个 Chromium Manifest V3 浏览器扩展，提供本地素材和草稿、批量发布计划、账号凭证保险箱、可恢复任务队列，以及供 AI 使用的 MCP 接口。扩展和本机桥接均没有运行时 npm 依赖。

当前交付是可安装的开发预览版。YouTube、WooCommerce、Shopify 已实现官方 API 请求流程；其余 28 个平台提供后台入口、文案准备与保守的表单辅助。真实账号发布仍需平台授权和现场验收，平台目录中的状态会明确显示这一区别。

## 安装

源码使用 Node.js 22 或更高版本构建：

```sh
npm run check
npm test
npm run build
```

构建不需要 `npm install`。打开 Chromium 的 `chrome://extensions`，启用开发者模式，点击“加载已解压的扩展程序”，选择仓库内的 `dist/chromium` 目录。点击 MatriXpost 图标打开完整工作区。也可以先解压 `dist/MatriXpost-chromium-0.5.0.zip`，再加载解压目录。

扩展要求 Chromium 120 或更高版本。当前实际浏览器验收使用 Linux Chromium；其他 Chromium 浏览器需要分别验收。Firefox 和 Safari 版本尚未交付。当前没有浏览器商店上架记录。

## 发布一个视频或商品

1. 在“账号管理”中新增账号。API 模式先设置保险箱口令，再填入该账号的授权凭证；店铺地址与平台账号身份创建后固定。
2. 在“创作”中选择视频或商品。视频文件保存到浏览器 IndexedDB；商品填写价格、币种、库存、SKU 和公开 HTTPS 图片地址。
3. 选择目标账号，保存本地草稿，然后检查发布计划。每个平台分别列出缺失字段、访问权限和执行方式。
4. 选择“保存到平台草稿 / 私密视频”或“发布视频 / 上架商品”，将通过检查的目标加入队列。可以指定计划时间。
5. 在“发布任务”查看进度、平台返回的 ID、状态与结果链接。浏览器运行且保险箱解锁时，队列会执行到期任务。

同一内容版本、同一账号和同一动作重复加入队列会返回已有任务。已完成的远端草稿随后正式发布时，会复用原视频或商品 ID。任务固定入队时的内容快照，之后编辑本地草稿不会改变已入队内容。

创作页辅助模式会准备文案并打开平台后台。“填入已打开页面”只填写唯一匹配、可见且为空的标题、描述、价格、SKU、库存字段；已有内容会保留，匹配失败会显示结果。视频文件、分类、资质和最终提交由你在平台页面完成。各平台实际页面的辅助效果仍需逐项现场验证。

## 平台能力

| 平台 | 当前实现 | 账号条件与范围 |
| --- | --- | --- |
| YouTube | 官方可恢复上传、8 MiB 分片、进度核对、私密上传、已有视频可见性更新 | 自己的 OAuth access token；上传需 `youtube.upload`，已有视频更新还需 `youtube.force-ssl` 等更新权限；返回视频 ID 后显示平台处理状态 |
| WooCommerce | 核对店铺币种，创建简单商品、草稿、上架及原位发布 | HTTPS 店铺，Read/Write Consumer Key 与 Secret；支持价格、SKU、数量和图片 |
| Shopify | 核对店铺币种，创建单规格商品、设置价格/SKU、可选库存、渠道发布 | 自有店铺 Admin API token；商品、库存、渠道需要对应权限和 Location / Publication ID；固定 API `2026-10` |
| 其他 28 个视频和电商平台 | 官方后台入口、文案准备、通用字段辅助 | 使用当前浏览器会话；自动提交适配器尚未接入 |

完整目录与限制见 [平台矩阵](docs/PLATFORMS.md)。商品适配器目前覆盖简单商品或单规格商品；复杂规格矩阵、市场税务、物流模板、资质文件和平台特有类目规则还需要后续适配。

## 多账号与隐私

API 账号各自保存独立凭证。凭证使用 Web Crypto 的 AES-GCM 加密，密钥由 12 字符以上口令通过 PBKDF2 派生。浏览器会话内保留解锁密钥，退出浏览器后需要重新解锁；口令无法找回。更新过期凭证时，应续期同一平台身份，任务会保留原检查点。

页面会话账号是后台入口与账号标签，使用当前浏览器配置的登录状态。同站点标签页共享登录会话；需要页面账号隔离时使用不同浏览器配置。MatriXpost 不读取或导出浏览器 Cookie，也不会把手填标签显示成已验证登录身份。

扩展没有遥测、远程脚本或内置模型服务。平台权限在添加账号或使用辅助填表时按目标地址申请。元数据备份包含草稿、账号标签和历史记录；不包含授权凭证、口令、上传会话地址或视频文件。备份导入只新增草稿和账号，执行任务不会被恢复运行。

## 原生 AI 操作

AI 通过 MCP 操作结构化对象，不依赖对页面截图进行点击。九个工具涵盖平台、账号、草稿、发布检查和任务管理。使用步骤和配置示例见 [AI 桥接说明](bridge/README.md)。

```sh
# 将实际扩展 ID 替换到参数中；在独立终端保持桥接运行。
node bridge/cli.mjs serve --extension-id YOUR_CHROMIUM_EXTENSION_ID
```

在扩展“AI 工作台”中输入桥接显示的本机地址和配对码。为 MCP 客户端配置 `node`、桥接 `cli.mjs` 的绝对路径及 `mcp` 子命令，通过 `MATRIXPOST_TOKEN` 环境变量或私有 token 文件传入相同配对码。扩展工作区打开期间会接收请求。

| MCP 工具 | 扩展操作 |
| --- | --- |
| `platforms_list` | 查询平台与能力 |
| `accounts_list` | 查询账号标签与接入方式，不返回凭证 |
| `drafts_list` / `drafts_save` | 查询、创建或按修订号更新草稿 |
| `publish_preview` | 检查目标、字段和权限 |
| `jobs_enqueue` | 生成固定内容与账号的任务 |
| `jobs_list` | 查询执行状态和平台结果 |
| `jobs_retry` / `jobs_cancel` | 重试明确失败的任务或取消待执行任务 |

AI 发起的公开发布任务显示完整内容快照，默认等待在工作区核对后批准。草稿动作可以直接进入队列。AI 接口无法解锁保险箱、读取凭证或自行批准公开发布。

## 任务恢复

队列将状态、远端 ID 和上传检查点持久化。YouTube 分片恢复前会先查询平台已接收的字节数。浏览器在创建商品或初始化上传时中断，可能导致平台已接收请求而本地尚未取得结果；这类任务会进入“结果待核对”，需要先查看平台，避免重新创建。对固定远端 ID 的原位发布可以恢复。

定时任务依赖浏览器运行，浏览器关闭期间不会执行。API 凭证过期时，任务停止并显示错误，更新同一账号的凭证后可重试。当前授权方式为手动配置 token/key；OAuth 登录应用注册和自动刷新尚未接入。

## 开发与验收

```sh
npm run check
npm test
npm run build

# 浏览器验收需要外部已安装的 Playwright 与 Chromium。
MATRIXPOST_PLAYWRIGHT_MODULE=/absolute/path/to/playwright \
MATRIXPOST_CHROMIUM=/usr/bin/chromium \
MATRIXPOST_PERMISSION_MODE=native \
node scripts/browser-test.mjs
```

单元与协议测试使用 fixture 响应和本机 HTTP 服务。浏览器脚本加载真实扩展，测试草稿、账号、保险箱、MCP、重启恢复与窄屏布局；它使用隔离配置并阻断外网发布。日常开发以本机验收为准，GitHub 工作流仅手动触发打包。

Linux 浏览器验收使用 `native` 权限模式，需要安装 `xvfb-run` 和 `dbus-run-session`。脚本创建独立 Xvfb 显示与 D-Bus 会话，在测试浏览器中请求 `https://example.com/*` 和 `http://127.0.0.1/*` 两个测试地址的访问权限。看到 `NATIVE_PERMISSION_WAIT` 后，通过能够查看该隔离显示的桌面工具检查 `test-results/permissions-native.png` 中的真实权限窗口，并点击“允许”；脚本随后核对浏览器实际授予的权限。这个步骤会等待真实点击，无法仅靠无头命令自动完成。成功页面截图会先回到页顶，最多等待 8 秒让临时提示消失；失败截图立即保留当时的现场。

本版完成 72 项核心与协议测试、12 项真实 Chromium 浏览器检查。具体环境、覆盖范围与尚未验证的部分见 [验收记录](docs/VALIDATION.md)。

目录结构和状态约定见 [架构说明](docs/ARCHITECTURE.md)。当前实现依据的官方接口资料列在 [平台矩阵](docs/PLATFORMS.md#官方资料) 中。
